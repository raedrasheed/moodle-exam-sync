# التجربة على نسختي Moodle المحليتين

هذا الدليل يستخدم نسختيك القائمتين. الأمثلة لا تفترض أسماء حاوياتك أو مسارات تثبيتك. خذ نقطة استعادة لقاعدة البيانات و`moodledata` لكل موقع قبل تركيب إصدار Alpha، واستخدم مقرّرًا وحسابات تجريبية.

## 1. التحقق من البيئة

يلزم Moodle 5.1 وPHP 8.2 أو أحدث مع امتدادات Moodle المعتادة، وإضافتي `mod_lti` و`enrol_lti` الأصليتين. اختُبر هذا المشروع آليًا على Moodle 5.1.3 و5.1.8+ مع PHP 8.3.6 وMariaDB 10.11.7.

إذا كان مصدر Moodle داخل حاوية Docker، نفّذ نسخ الإضافات على المجلد المركّب الذي يحوي المصدر، وشغّل PHP داخل حاوية التطبيق. حاوية قاعدة البيانات وحدها ليست مكان تشغيل أوامر Moodle.

تأكد أن المتصفح **وكل خادم PHP** يستطيعان الوصول إلى رابط الموقعين. `localhost` داخل كل حاوية يشير إلى الحاوية نفسها. استعمل اسمين ثابتين يمكن حلهما من المتصفح والحاويات، مع مطابقة `$CFG->wwwroot` للرابط الذي يُفتح فعليًا. استخدم البروتوكول نفسه للموقعين؛ يمكن HTTP في مختبر معزول مع `labhttp=1`، واستخدم HTTPS للبيانات الحقيقية.

## 2. تركيب الإضافتين

من مجلد المستودع:

```bash
python3 tools/install.py /absolute/path/to/main-moodle
python3 tools/install.py /absolute/path/to/exam-moodle
```

يكتشف المثبت مجلد `public` في Moodle 5.1. ينشئ:

```text
public/local/examsync
public/mod/quiz/accessrule/examsync
```

شغّل الترقية في كل نسخة، بالمستخدم الذي يشغّل Moodle:

```bash
php /absolute/path/to/main-moodle/public/admin/cli/upgrade.php --non-interactive
php /absolute/path/to/exam-moodle/public/admin/cli/upgrade.php --non-interactive
```

للتحديث لاحقًا: أضف `--update` إلى المثبت. يحفظ نسخة من مجلدي الإضافة السابقين قبل استبدالهما. هذا لا يعوّض نسخة قاعدة البيانات عند الرجوع إلى إصدار سابق.

## 3. تسجيل LTI بين الموقعين

في **موقع الاختبارات** فعّل مصادقة LTI وطريقة التسجيل «النشر كأداة LTI». من إعدادات هذه الطريقة افتح تسجيل الأدوات، وسجّل منصة جديدة للموقع الرئيسي وانسخ رابط التسجيل الديناميكي. في **الموقع الرئيسي** افتح إدارة الأدوات الخارجية، وأضف الرابط عبر LTI Advantage ثم فعّل الأداة. تحقق من ظهور تسجيل المنصة نشطًا في موقع الاختبارات.

استخرج رقم نوع الأداة من صفحة تعديل الأداة في الرئيسي (`id` في رابط الإعدادات) وضعه في `ltitypeid`. استخدم رابط `$CFG->wwwroot` الخاص بالموقع الرئيسي حرفيًا كقيمة `issuer` في موقع الاختبارات. لا تُنشئ موارد الاختبارات أو روابطها يدويًا؛ الإضافة تنشئها لكل اختبار بعد نجاح الاستعادة.

مرجع التسجيل الرسمي: [Moodle to Moodle LTI 1.3](https://docs.moodle.org/501/en/LTI_Moodle_to_Moodle).

## 4. إعداد الاتصال

انسخ `examples/source.example.json` و`examples/target.example.json` إلى مكان خاص خارج المستودع. غيّر الروابط والأرقام حسب نسختيك، وضع مفتاحًا عشوائيًا واحدًا في الملفين. يمكن توليده محليًا:

```bash
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

لا ترسل المفتاح في المحادثة ولا ترفعه إلى GitHub. الأرقام `4` و`5` هي أمثلة شائعة؛ تحقق من دور المدرس غير المحرر ودور الطالب عندك. فحص الإعدادات يتحقق من نوع الدور.

```bash
php /absolute/path/to/main-moodle/public/local/examsync/cli/configure.php --file=/secure/path/source.json
php /absolute/path/to/exam-moodle/public/local/examsync/cli/configure.php --file=/secure/path/target.json
php /absolute/path/to/main-moodle/public/local/examsync/cli/check.php --peer
php /absolute/path/to/exam-moodle/public/local/examsync/cli/check.php --peer
```

يمكن تعديل الإعدادات أيضًا من «إدارة الموقع ← الإضافات المحلية ← مزامنة الاختبارات». لا تغيّر هوية الاقتران أو `issuer` بعد إنشاء الاختبارات؛ ربط حسابات LTI يعتمد عليهما.

إذا نجح الوصول في المتصفح وفشل `--peer`، افحص DNS داخل PHP، منافذ Docker، الوقت على الخادمين، ثم إعدادات Moodle «أمان HTTP». تحترم الإضافة قائمة مضيفي cURL المحظورين والمنافذ المسموحة؛ أجِز عنوان الخادم المقابل ومنافذه ضمن سياسة مختبرك. لا تعطل التحقق من شهادات TLS. تحقق أيضًا من أن حد جسم الطلب في خادم الويب يسمح بطلبات 2 MiB.

## 5. تشغيل المهام

شغّل cron المعتاد في كل موقع كل دقيقة. للتجربة اليدوية:

```bash
php /absolute/path/to/main-moodle/public/admin/cli/cron.php
php /absolute/path/to/exam-moodle/public/admin/cli/cron.php
php /absolute/path/to/main-moodle/public/admin/cli/cron.php
```

مهلة تجميع تعديلات المحتوى الافتراضية 30 ثانية؛ أعد تشغيل cron بعد استحقاق المهام. ترتيب المصدر ثم الهدف ثم المصدر يعكس النقل والاستعادة ثم إنشاء الرابط. يواصل cron المنتظم بقية العمل تلقائيًا. عند الفشل راجع «مهام مخصصة / Ad hoc tasks» و«سجلات المهام» في إدارة الموقع، وصفحة المزامنة في المقرر.

مرجع التشغيل: [Moodle cron](https://docs.moodle.org/501/en/Cron).

## 6. التجربة والرجوع

نفّذ [قائمة القبول](ACCEPTANCE.ar.md). لا تعتبر نجاح فحص الاتصال بديلًا لتجربة طالب من المتصفح على الموقعين. بعد التأكد من القبول يمكن التخطيط للنشر مع نسخ احتياطي ومراجعة إعدادات الإنتاج؛ لا تُنسخ مفاتيح المختبر إلى الإنتاج.

للرجوع في المختبر استعد قاعدة البيانات و`moodledata` ومجلدي الإضافة من نقطة الاستعادة نفسها. لا تحذف قاعدة الوصول وحدها أثناء وجود اختبارات متزامنة، لأن حمايتها جزء من مسار بدء المحاولة.
